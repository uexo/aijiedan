Design System v3 · 2026-10-20

凭证 / 档案

产品的核心资产是"不可伪造的记录"，界面就该长得像记录。所以这套视觉不是 SaaS 蓝玻璃，是纸、墨、印章——安静、可核对、不像营销页。

E-Ink Paper Swiss Modernism 2.0 单一强调色 无 emoji 图标 WCAG AA

04 该做与不该做

维度做不做
装饰留白、细线、纸纹渐变玻璃、彩色投影、发光边框
图标线性 SVG（1.8–2px 描边）emoji、"金牌""钻石"类徽章
数字等宽、可点开溯源评分、等级、匹配度百分比
动效150–250ms 淡入位移弹跳、缩放、视差、滚动跑马灯
文案陈述事实 + 主动暴露缺点"AI 认为他很合适"、夸张形容词
人像姓名首字印章AI 生成假头像、通用剪影
说服证据、订单号、原文倒计时、剩余名额、社会认同刷屏

05 与 PRD 的对应

每个设计决策都能回溯到一条需求，避免"看起来更完整"的功能混进来。

需求设计落点关键约束
FR-01post 页三步：一句话 → 抽取可改 → 发布必填仅两项；≤3 步到候选人；缺验收标准时标红
FR-02固定 3 张卡片，第 4 个位置是"改写需求"不多不少，不做"加载更多"
FR-03每卡 3 条理由 + ↗ 事实锚点无锚点的理由不许出现
FR-04卡片结构：人 → 背书人 → 原话 → 数据 → 两按钮首屏不滚动看完全部核心信息
FR-05flow 页四态状态机 + 取消支线不可跳步，无进度百分比
FR-06验收按钮 + 交付物清单 + 审计时间线平台只记录事实，不碰钱
FR-07三问勾选 + 12 字实时门禁 + 不可编辑提示前端硬校验，低于门槛按钮禁用并说明差多少
FR-08credit 页免登录 + 导出 PDF/图片 + 短链无登录墙、无二维码引导下载 App
FR-09"无订单背书 0" 上榜 + "背书较少"诚实标注宁可少，不可假

06 无障碍与实现

硬指标
  • · 正文对比度 ≥ 4.5:1（ink / ink-2 / ink-3 均达标）
  • · 可点区域 ≥ 40×40（移动端 ≥ 44）
  • · 焦点环 2px 印章红 + 3px 偏移，键盘可走完全流程
  • · 状态不只靠颜色：圆点 + 文字双编码
  • · 尊重 prefers-reduced-motion，关闭全部动画
落地方式
  • · 纯静态、零构建：web/v3/ds.css + 9 个 HTML
  • · Go 侧只需把 /static/v3/ 挂上，API 复用现有 REST
  • · 不做前端框架迁移，不做组件库重写
  • · 纯本地字体栈，零外部请求（预览环境 CSP 会拦远程字体）
  • · 现有 web/ 保留为 escrow 模式（旧回归 147 项不受影响）

07 页面清单与走法

九页。公开四页，登录后五页。没有一页是"以后可能要"。

页面可见性解决什么从哪进
index公开说清这是什么、不是什么直接访问
auth公开手机号验证码，一个号一个身份顶栏「登录」、发单前置
credit公开把信誉带走：打印、长图、短链任何人分享的链接
system公开这页设计系统本身首页页脚
post登录一句话发需求，三步到候选人顶栏「发一句话需求」
match登录3 张卡片，看出该选谁发单后自动进入
flow登录四态推进、验收、写背书卡片「发起合作」、待办
app登录待办、订单、档案三件事登录后默认（需求方）
profile登录供给方档案，被推荐的前提登录后默认（供给方）、顶栏
主路径只有一条：index → post → match → flow → credit。auth 是前置，app 和 profile 是回访入口。 任何页面都必须能一次点击回到这条主路径上，不留断头路。
